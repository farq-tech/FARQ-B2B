# فرق أطلس

**الهدف:** بناء واجهة فرق الجديدة التي تجعل المستخدم يرى السوق، يحدد الجهات، يراجع اختياره، ثم ينشئ طلباً أو مسودة بإرادته ومن دون إرسال تلقائي.

**النطاق العام:** `atlas.farq.sa`

**نقطة الدخول:** تبقى الصفحة التعريفية العامة موجودة على النطاق الجديد، ثم ينتقل المستخدم إلى المنصة بعد تسجيل الدخول.

**مسار المستخدم:** هدف → بحث ونطاق → خريطة ونتائج متزامنة → اختيار جهات → مراجعة → طلب تسعير أو مسودة حملة → تأكيد إرسال منفصل.

**حالة التنفيذ:** تعمل خدمة `farq-atlas` على Railway، و`https://atlas.farq.sa` متاح بشهادة HTTPS صالحة. طبقة السوق تقرأ مضلعات الأحياء والإحصاءات التجميعية الحية عبر مسار خادمي للقراءة فقط؛ لا تعرض بيانات نموذجية عند تعذر الخدمة. أضيفت جلسة دخول مستقلة في أطلس، تحفظ رموز الحساب داخل ملف تعريف ارتباط مشفّر و`HttpOnly`. مسار الجهات الحية لا يعمل إلا بعد تسجيل الدخول ويتحقق من الحساب قبل الاتصال بالدليل، ويعيد بيانات القرار فقط (الاسم، النشاط، الموقع، وإشارة واتساب) من دون أرقام اتصال أو بريد. أي إرسال يبقى خارج هذا المسار.

**مبدأ الانتقال:** لا يُستبدل النظام القائم أو نطاقاته قبل مراجعة أطلس وربطه بالبيانات الفعلية والتحقق من المسار كاملاً.


## عقد بيانات الجهات الحية

- `POST /api/session/login`: يستقبل البريد وكلمة المرور، ويعيد المستخدم وتاريخ انتهاء الجلسة فقط. رموز الدخول لا تصل إلى المتصفح.
- `GET /api/session/me`: يعيد حالة جلسة أطلس العامة.
- `POST /api/session/logout`: ينهي جلسة أطلس.
- `POST /api/market/entities`: يتطلب جلسة صالحة وطلباً يحتوي `q` و`city` و`limit` اختياري حتى 50. يعيد أسماء الجهات، النشاط، الحي، الموقع، سبب المطابقة، وحالة واتساب؛ وتنعكس المواقع كنقاط عند مستوى المنشآت فقط. لا يعيد رقم هاتف أو بريد أو أي إجراء إرسال.
- الوصول إلى هذا المسار يُضبط اختيارياً عبر `ATLAS_TARGETING_ALLOWED_EMAILS`.
