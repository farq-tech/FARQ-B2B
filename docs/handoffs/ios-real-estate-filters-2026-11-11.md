# تسليم: فلاتر الباحث عن العقار في iOS

**الفرع:** `codex/ios-real-estate-filters`  
**الأساس:** `codex/atlas-property-filter-accuracy` (PR #756)، المبني على `codex/atlas-district-geometry-sanitize` (PR #754)

## ما تغيّر

- شاشة بداية العقار تجمع الإيجار أو الشراء، نوع العقار، مدة الإيجار، حد الغرف، عمر العقار، الميزانية، كثافة الحي، واختيار الأحياء بالاسم مع البحث.
- ميزانية الشراء مستقلة عن الإيجار السنوي والشهري. تغيير مدة الإيجار يمسح الميزانية السابقة لتجنب تطبيق حد بوحدة مختلفة.
- يرسل التطبيق معايير البحث إلى API قبل حد النتائج، بدلاً من جلب قائمة عامة ومحاولة تصفيتها محلياً.
- إذا فعّل المستخدم كثافة السكان، تبقى الأحياء ذات الكثافة المفقودة خارج النتائج؛ لا تتحول البيانات المفقودة إلى صفر.
- يبقى المسار ثلاث شاشات: اختيار المواصفات، النتائج، ثم تفاصيل العرض.

## اعتماد الدمج

هذا الفرع يعتمد على حقول `/real-estate-listings` التي يضيفها PR #756، بما فيها `deal`, `district_ids`, `min_beds`, `max_age`, `max_price`, و`min_density`. وسلسلة الفروع تبدأ بـ PR #754 إلى `master`، ثم #756، ثم هذا الفرع. راجعها وادمجها بهذا الترتيب، وانشر API قبل دمج التطبيق أو إصدار TestFlight. لا تدمج هذا الفرع مع `master` قبل اعتماد API.

## التحقق

- `corepack pnpm build` من `apps/atlas`: ناجح.
- `python3 -m unittest` من `services/targeting-api`: 678 اختباراً ناجحاً.
- اختبارات وحدة iOS: 7 ناجحة. اختبار واجهة رحلة العقار المركّز يمرّ على اختيار النوع والغرف وفتح تفاصيل العرض.
- التشغيل الأول للمجموعة الكاملة فشل في حدّي زمن قديمين لمسارين آخرين: فتح جدول المحللين استغرق 4.82s مقابل حد 3s، وفتح تفاصيل حي الجمهور استغرق 2.18s مقابل حد 2s. يحتاج المدير التقني لتقرير هل يعيد القياس على جهاز مستقر أو يفتح متابعة أداء؛ لم تُعد المجموعة كاملة بعد تصحيح مسار العقار.
- `git diff --check`: أعد تشغيله بعد آخر تعديل وقبل رفع الفرع.
